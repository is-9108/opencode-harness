## 導入の手順（M1 では手動。M5 で導入スクリプトにする）

1. 開発対象のリポジトリに、このリポジトリの次のファイルをコピーする
   - `.opencode/agents/`、`.opencode/commands/`、`.opencode/plugins/`、`.opencode/templates/`
   - `.opencode/harness/`（`test/` は除く）
   - `.opencode/templates/github/pull_request_template.md` → `.github/pull_request_template.md`
2. `harness.config.json` を作る（`harness.config.example.json` を元に、モデル・checks・tests.globs・setup.install を設定する）
3. `.gitignore` に `node_modules/` と `.harness/` を入れる
4. これらをベースブランチに commit して push する（子セッションは worktree 側の `.opencode/` のエージェント定義で動くため、ベースブランチに入っている必要がある）
5. `gh auth login` 済みで、git の `user.name` / `user.email` が設定されていること

## 実行の手順

TUI で `/dev <issue番号>` を実行し、計画の承認に答える。

E2E では TUI の代わりに、`opencode serve` と [spikes/m1/drive-dev.mjs](../../spikes/m1/drive-dev.mjs) で同じ操作を行った。

```
cd <試験用リポジトリ>
opencode serve --port 4097
ISSUE=1 APPROVALS=1 MODEL=openai/gpt-6-luna node spikes/m1/drive-dev.mjs   # 最初の問いで承認する
```

AC-2 は、green の子セッションが作られた後にサーバ（`opencode serve`）のプロセスを強制終了し、起動し直してから `/dev 2` を再実行して確かめた。

## 見つかった問題と対応

| # | 問題 | 対応 |
|---|---|---|
| 1 | **子セッションの ID が、子セッションが終わってからしか保存されなかった**。green の最中に強制終了すると ID が残らず、再開すると新しい子セッションでやり直しになった（1 回目の強制終了で確認） | `runChild` に `onSession` を追加し、子セッションを作った直後に red / green が ID を保存するようにした（この PR）。2 回目の強制終了では、同じ子セッションで続きから進むことを確認した |
| 2 | 強制終了で中断された子セッションのトークン数は `child.completed` が出ないので、記録されない（issue #2 の green は再開後の分だけ） | M3 の予算の実装で、中断時にもトークンを集計するようにする（未対応） |
| 3 | 確認用スクリプトが、司令塔の問いの文面に「具体的な」とあるのを見て、修正内容を聞かれたと誤判定し、無関係な修正指示を答えた | スクリプトを修正（選択肢に「承認」があれば選択肢から選ぶ）。ハーネスの問題ではない。やり直した run で AC-1 を確かめた |
| 4 | worktree のブランチには、作った時点のベースブランチの `.opencode/` が入る。ハーネスを更新しても、作成済みの worktree の子セッションのエージェント定義は古いまま | 現状は仕様として扱う（プラグインのコードは本体側で動くので、エージェント定義の変更だけが影響する）。M5 の導入スクリプトで扱いを決める |
| 5 | `escalated` になった run を戻す手段がない（M1 の確認では state.json を手で書き換えた） | M2 の `/fix` で扱う |
